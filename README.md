# Информационная система ООО «Обувь»

Готовое учебное решение по заданию демонстрационного экзамена: база данных + приложение для магазина обуви с авторизацией, ролями, товарами, заказами, поиском, фильтрацией и CRUD-операциями.

## 1. Что реализовано

### Модуль 1 — база данных

- Спроектирована SQLite-база данных в 3 нормальной форме.
- Созданы таблицы: роли, пользователи, товары, категории, производители, поставщики, единицы измерения, заказы, статусы заказов, пункты выдачи, состав заказов.
- Добавлены первичные и внешние ключи.
- Настроена ссылочная целостность.
- Добавлены ограничения: цена, количество и скидка не могут быть отрицательными.
- Товар, который используется в заказе, нельзя удалить.
- Подготовлена ER-диаграмма: `docs/module_1_er_diagram.pdf`.
- Подготовлен SQL-скрипт: `database/schema.sql`.

### Модуль 2 — алгоритм и приложение

- Сделано окно входа, которое открывается первым.
- Есть авторизация по логину и паролю из БД.
- Есть вход в роли гостя.
- После входа отображаются ФИО пользователя и роль.
- Есть кнопка выхода обратно на экран входа.
- Подготовлена блок-схема алгоритма: `docs/module_2_algorithm_flowchart.pdf`.
- Интерфейс оформлен по стилю задания: Times New Roman, белый фон, зеленый дополнительный цвет, акцентный цвет.

### Модуль 3 — товары

- Реализован список товаров из БД.
- Для товара выводятся: фото, категория, название, описание, производитель, поставщик, цена, единица измерения, количество на складе, скидка.
- Если фото отсутствует, используется `resources/picture.png`.
- Если скидка больше 15%, карточка товара подсвечивается цветом `#2E8B57`.
- Если товара нет на складе, карточка подсвечивается голубым цветом.
- Если есть скидка, старая цена красная и зачеркнутая, итоговая цена черная.
- Для менеджера и администратора есть поиск, сортировка по количеству и фильтр по поставщику.
- Поиск, сортировка и фильтр работают в реальном времени и совместно.
- Для администратора есть добавление, редактирование и удаление товаров.
- При замене изображения старое изображение из папки приложения удаляется.
- Фото товара сохраняется в `resources/images` и приводится к размеру 300x200 px при наличии Pillow.

### Модуль 4 — заказы

- Для менеджера и администратора добавлена кнопка «Заказы».
- Менеджер может просматривать заказы.
- Администратор может добавлять, редактировать и удалять заказы.
- На форме заказа есть: артикул, статус заказа, адрес пункта выдачи, дата заказа, дата выдачи.
- После добавления, редактирования или удаления список заказов обновляется.

## 3. Как запустить

### Вариант 1. Быстрый запуск с тестовыми данными

1. Установить Python 3.10+.
2. Открыть терминал в папке проекта.
3. Установить зависимости:

```bash
pip install -r requirements.txt
```

4. Запустить приложение:

```bash
python run.py
```

При первом запуске автоматически создается файл базы данных `shoe_store.sqlite3` и загружаются тестовые данные.

### Вариант 2. Запуск с импортом реальных данных из Приложения 2

1. Распаковать архив `Прил_2_ОЗ_КОД 09.02.07-2-2026-М1.rar`.
2. Скопировать файлы `Tovar.xlsx`, `user_import.xlsx`, `Заказ_import.xlsx`, `Пункты выдачи_import.xlsx` в папку:

```text
resources/import/
```

3. Выполнить импорт:

```bash
python database/import_from_excel.py --dir resources/import
```

4. Запустить приложение:

```bash
python run.py
```

## 6. Проверка без интерфейса

Для быстрой проверки сервисного слоя можно выполнить:

```bash
python tests/smoke_test.py
```

Скрипт создаст БД, проверит авторизацию и выведет количество товаров и заказов.

## 7. Примечания

- Решение сделано на Python + Tkinter + SQLite, чтобы его можно было запустить без отдельного сервера БД.
- `Pillow` используется только для корректной работы с изображениями и изменения размера фото до 300x200 px.
- Если `Pillow` не установлен, приложение продолжит работать, но возможности обработки изображений будут ограничены.
- Архив с исходными данными из приложения 2 положен в `resources/import/` для удобства, но в самой среде подготовки проекта RAR-файл не был распакован автоматически. Для импорта реальных данных его нужно распаковать локально и положить Excel-файлы в `resources/import/`.
